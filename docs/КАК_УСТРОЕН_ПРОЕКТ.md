# Как устроен проект «Фитнес»

Этот файл — учебник по твоему же приложению. Здесь описано, из чего оно собрано, зачем
нужна каждая технология, где лежит код и как по нему ходить. Читать можно по порядку или
разделами. В конце — словарь терминов и план, что изучать дальше.

Объём на октябрь 2026: около 22 000 строк кода приложения, 6 400 строк тестов (294 теста),
1 200 строк Kotlin/Java для Android.

---

## 1. Общая картина

Приложение — это **веб-приложение**: HTML, CSS и JavaScript, которые работают в браузере.
Одно и то же приложение попадает к людям тремя путями:

```
                     исходный код (frontend/src, TypeScript + React)
                                     │
                              npm run build (Vite)
                                     │
                               frontend/dist/
                     (готовые HTML, JS, CSS, картинки)
              ┌──────────────────────┼───────────────────────┐
              ▼                      ▼                       ▼
     GitHub Pages (сайт)     Capacitor → Android      Сайт на экране «Домой»
   r4048731-cpu.github.io      APK (fitnes.apk)        iPhone/Android (PWA)
       /fintesrust/          + нативные модули:
                             шаги, GPS в фоне,
                             уведомления, голос
```

**Сервера нет.** Все данные (тренировки, вес, питание, пробежки) хранятся в базе прямо в
телефоне — в IndexedDB браузера. Поэтому приложение бесплатное, работает без интернета, и
чужие данные никто не видит. Минус: при потере телефона данные пропадут, если не сделать
резервную копию (Настройки → Резервная копия, JSON-файл).

## 4. Слои: главная идея архитектуры

Код разделён на слои, и каждый слой знает только о тех, что ниже:

```
   screens/ + components/      что видит пользователь (React)
              │ вызывает
              ▼
          data/repositories    как сохранить и достать (Dexie)
              │ использует
              ▼
           domain/             что посчитать (обычные функции)
```

**Почему так.** Расчёты в `domain/` — это обычные функции «получил данные → вернул
результат». Их легко проверять тестами, в них не нужно разбираться с базой или экраном.
Например, `src/domain/oneRM.ts` считает одноповторный максимум, `src/domain/runIntervals.ts`
— фазы интервального бега, `src/domain/metrics.ts` — тоннаж и рекорды.

**Репозиторий** (`src/data/repositories/*.ts`) — объект с методами для одной таблицы:
`workouts.start()`, `workouts.finish()`, `runs.getActive()`… Экран не пишет в базу сам, а
просит репозиторий. Все репозитории собираются в `createRepositories()` (`src/data/index.ts`)
и раздаются экранам через **контекст React** (`src/app/DataProvider.tsx`). Экран получает
их хуком `useRepos()`.

Зачем: в тестах вместо настоящей базы подставляется временная (`tests/helpers.ts` →
`setup()`), а экраны об этом даже не знают.

### Пример пути данных: «Завершить тренировку»

1. `screens/WorkoutScreen.tsx` — пользователь жмёт кнопку, вызывается
   `repos.workouts.finish(...)`.
2. `data/repositories/workouts.ts` — берёт тренировку из базы, вызывает расчёты из
   `domain/metrics.ts` (`findNewRecords` — новые рекорды), сохраняет результат.
3. Dexie замечает изменение таблицы `workouts` — все экраны, которые читают её через
   `useLiveQuery`, перерисовываются сами (история, прогресс, «Сегодня»).
4. Экран переходит на `/workout/:id/summary` — итог тренировки.

## 5. React — что используется и где посмотреть

| Понятие | Простыми словами | Пример в коде |
|---|---|---|
| **Компонент** | Функция, возвращающая кусок интерфейса (JSX — HTML внутри JS) | `src/components/Button.tsx` |
| **Props** | Параметры компонента | `interface Props` в `src/screens/today/WeekStrip.tsx` |
| **useState** | Значение, при изменении которого компонент перерисуется | почти любой экран |
| **useEffect** | «Сделать что-то после отрисовки»: таймер, подписка, GPS | `src/app/hooks/useNow.ts` |
| **useRef** | Значение, которое помнится между отрисовками, но не вызывает перерисовку | `announcedPhase` в `RunActiveScreen.tsx` |
| **Свой хук** | Функция `useЧто-то`, объединяющая хуки для повторного использования | `useNow`, `useWakeLock`, `screens/today/useToday.ts` |
| **Context** | Передать значение всем вложенным компонентам без пробрасывания через props | `DataProvider` → `useRepos()` |
| **useLiveQuery** (Dexie) | Запрос к базе, который сам обновляется при изменении данных | `src/screens/NotesScreen.tsx` |
| **CSS Modules** | `import styles from './X.module.css'` → `className={styles.card}` | любой экран |

**Тема.** Цвета заданы переменными CSS (`--bg`, `--text`, `--gradient`…) в
`src/app/theme.css`. Тёмная тема — те же переменные с другими значениями. Выбор хранится в
`localStorage` (`src/app/theme.ts`), потому что это настройка вида, а не данные.

**Шторки** (выезжающие снизу панели) — `src/components/Sheet.tsx`, на нём построены почти
все формы: `MealSheet`, `OneRMSheet`, `PlatesSheet`…

## 6. Данные: IndexedDB и Dexie

**IndexedDB** — база данных, встроенная в каждый браузер. Хранит объекты, работает без
сервера. Данные живут у конкретного сайта в конкретном браузере.

Схема — `src/data/db.ts`. Таблицы:

| Таблица | Что хранит | С какой версии схемы |
|---|---|---|
| `exercises` | справочник упражнений | 1 |
| `programs` | программы и дни | 1 |
| `workouts` | тренировки с подходами | 1 |
| `meta` | настройки и разное (ключ → значение) | 1 |
| `bodyWeights` | вес тела | 2 |
| `meals` | дневник питания | 3 |
| `notes` | заметки | 4 |
| `recipes` | свои рецепты | 5 |
| `runs` | пробежки по GPS | 6 |
| `photos` | фото прогресса | 7 |
| `measurements` | замеры тела | 8 |

**Версии схемы (миграции).** Когда нужна новая таблица, нельзя просто поменять старую
схему — у людей уже есть данные. Поэтому добавляется `this.version(9).stores({...})`, и
Dexie при запуске сам обновит базу. Старые версии в коде не удаляются никогда.

**Строка индексов** `'id, date, status, *exerciseIds'` — по каким полям можно быстро
искать. `*` — индекс по массиву (найти тренировки, где было упражнение X).

**Поля `id`, `updatedAt`, `deletedAt`** есть у всех записей (`Syncable` в
`src/domain/types.ts`). `id` — случайный UUID (`src/domain/id.ts`). Удаление «мягкое»:
запись не стирается, а помечается `deletedAt`. Это задел под синхронизацию: другое
устройство должно узнать, что запись удалили.

**Резервная копия** — `src/data/backup.ts`: вся база в один JSON-файл и обратно. В файле
есть `BACKUP_VERSION`, чтобы старые копии читались новой версией приложения.

**Стартовые данные** — `src/data/seed.ts`: справочник упражнений при первом запуске.

## 7. Навигация

`src/app/routes.tsx` — список адресов и экранов. Используется **хэш-роутинг**: адреса
выглядят как `…/fintesrust/#/programs`. Почему: GitHub Pages — простой хостинг, он не
умеет на любой адрес отдавать `index.html`. Всё, что после `#`, браузер на сервер не
отправляет — так любой экран открывается по ссылке.

Экраны внутри `Layout` получают шапку и нижнюю панель вкладок (`src/app/Layout.tsx`).
Тренировка, бег и таймер вынесены наружу — они на весь экран.

## 8. PWA: установка и работа без интернета

**PWA** (Progressive Web App) — сайт, который ведёт себя как приложение. Для этого нужно:

- **манифест** — имя, иконки, цвета (`manifest` в `vite.config.ts`);
- **service worker** — скрипт-посредник между приложением и сетью. При первом открытии он
  скачивает все файлы приложения в кэш, и дальше оно открывается без интернета.
  Генерируется плагином `vite-plugin-pwa` (внутри — библиотека Workbox Google);
- **HTTPS** — без него браузер не даёт ни service worker, ни GPS.

`registerType: 'autoUpdate'` — когда на сайте выходит новая версия, service worker сам её
скачает и подменит.

`navigateFallbackDenylist` — исключения: `install.html` и `fitnes.apk` не подменяются
приложением.

**Защищённый контекст.** Часть возможностей браузера (GPS, `crypto.randomUUID`,
блокировка экрана) работает только по HTTPS или на `localhost`. Поэтому по адресу
`http://192.168.0.113:5173` (телефон в домашней сети) GPS не работает — это было причиной
бага на этапе 9.

## 9. Android-версия: Capacitor

**Capacitor** берёт готовую папку `dist/` и кладёт её внутрь Android-приложения. Внутри
работает **WebView** — встроенный браузер. Снаружи — обычное Android-приложение, которое
может делать то, что сайту запрещено.

**Плагин** — мост между JavaScript и Kotlin. Как это устроено на примере шагов:

```
src/native/steps.ts                       android/.../steps/StepsPlugin.kt
registerPlugin<StepsPlugin>('Steps')  ⇄   @CapacitorPlugin(name = "Steps")
Steps.daily({ days: 7 })              →   @PluginMethod fun daily(call) { … call.resolve(…) }
```

JS вызывает метод → Capacitor передаёт вызов в Kotlin → Kotlin отвечает → в JS приходит
`Promise` с результатом. Плагины регистрируются в `MainActivity.java`.

| Плагин | Что делает | Файлы |
|---|---|---|
| `Steps` | шаги за день из Health Connect, вечернее напоминание о цели | `steps/*.kt`, `src/native/steps.ts` |
| `RunTracker` | **служба переднего плана**: GPS и голос интервалов при выключенном экране | `run/*.kt`, `src/native/runTracker.ts` |
| `WorkoutAlerts` | будильник конца отдыха, напоминание о тренировке | `workout/*.kt`, `src/native/workoutAlerts.ts` |
| `ShareImage` | «Поделиться» картинкой итогов месяца | `share/*.kt`, `src/native/shareImage.ts` |

**Служба переднего плана** (foreground service) — Android усыпляет фоновые приложения, но
не трогает службу, которая показывает постоянное уведомление («Идёт бег»). Пока она
работает, GPS пишется, а голос (`TextToSpeech`) объявляет смену интервалов — даже когда
WebView со страницей спит.

Права приложения (геолокация, уведомления, шаги) перечислены в
`android/app/src/main/AndroidManifest.xml`.

Как узнать в JS, что мы в Android-версии: `isAndroidApp()` из `src/native/steps.ts`.

## 10. Тесты

Команда: `npm test` (в `frontend/`). На этом компьютере лучше
`npx vitest run --maxWorkers=6` — иначе 44 файла сразу перегружают 12 ядер и тесты падают
по таймауту.

Два вида тестов:

- **Расчёты** (`tests/metrics.test.ts`, `oneRM.test.tsx`…) — вызвать функцию из `domain/`
  и сравнить результат: `expect(runIntervalsSec(c)).toBe(660)`.
- **Экраны** (`tests/workout-screen.test.tsx`, `runIntervals.test.tsx`…) — отрисовать
  экран в поддельном браузере (jsdom) и действовать как человек: найти кнопку по надписи,
  нажать, проверить текст. Testing Library специально ищет элементы по ролям и подписям
  (`getByRole('button', { name: 'Старт' })`) — заодно это проверяет доступность для
  экранного диктора.

Полезные приёмы из `tests/helpers.ts`:

- `setup()` — новая пустая база для каждого теста;
- `manualClock()` — «ручные часы»: время в тестах не зависит от реальной даты,
  `clock.advance(5 * 60_000)` — промотать 5 минут.

## 12. Git, GitHub и публикация

**Git** хранит историю: каждый **коммит** — снимок проекта с описанием. `git log --oneline`
— посмотреть историю, `git diff` — что изменилось и ещё не закоммичено.

**Публикация сайта — это пуш в ветку `main`:**

```
git push origin main
      │
      ▼  GitHub Actions (.github/workflows/deploy.yml)
  npm ci → lint → typecheck → test → build → копия APK в dist → GitHub Pages
      │
      ▼  через 2–3 минуты
https://r4048731-cpu.github.io/fintesrust/              — приложение
https://r4048731-cpu.github.io/fintesrust/install.html  — страница установки
```

**Важно про APK:** GitHub сам Android-приложение не собирает, он берёт готовый файл
`frontend/apk/fitnes.apk`. Если менялось приложение — перед пушем выполнить `npm run apk`.

## 13. Шпаргалка команд

Все команды — из папки `frontend/`.

```bash
npm install            # поставить зависимости (после git clone или смены package.json)
npm run dev            # сервер разработки на http://localhost:5173
npm run dev -- --host  # то же, но доступно телефону в домашней сети (без GPS)
npm test               # тесты
npm run build          # собрать сайт в dist/
npm run preview        # открыть собранный dist/ как на настоящем сайте
npm run apk            # собрать Android-приложение → apk/fitnes.apk
```

Сборка Android вручную (то, что делает `npm run apk`):

```bash
npm run build                       # 1. собрать сайт
npx cap sync android                # 2. скопировать dist/ в Android-проект
cd android
JAVA_HOME=~/.local/jdk-21 ./gradlew --offline assembleDebug   # 3. собрать APK (нужна Java 21)
# результат: android/app/build/outputs/apk/debug/app-debug.apk
```

**Gradle** — сборщик Android-проектов (как Vite для веба). `assembleDebug` — отладочная
сборка, подписанная ключом из `~/.android/debug.keystore`. Пока APK подписаны одним ключом,
новая версия ставится поверх старой с сохранением данных.

## 14. Как добавить новую функцию (по шагам)

Так делался, например, интервальный бег:

1. **Тип** — что храним. `RunIntervals` в `src/domain/run.ts`, необязательное поле
   `intervals?` у пробежки (старые записи без него остаются корректными).
2. **Расчёты** — новый файл `src/domain/runIntervals.ts`: фазы, «где мы сейчас», фразы для
   голоса. Без React и базы.
3. **Тесты на расчёты** — `tests/runIntervals.test.tsx`.
4. **База** — нужна ли новая таблица? Если да — `version(n+1)` в `db.ts`. Здесь хватило
   поля в существующей таблице, а `runs.start()` в репозитории получил параметр.
5. **Экран** — `RunScreen.tsx` (выбор), `RunActiveScreen.tsx` (во время бега),
   `RunDetailScreen.tsx` (итог). Стили — в их `.module.css`.
6. **Тест экрана** — нажать кнопки, как человек, проверить результат.
7. **Android**, если нужно то, чего не умеет браузер, — Kotlin в `android/…`, мост в
   `src/native/`.
8. Проверки (раздел 11) → коммит → `npm run apk` → пуш.

## 15. Словарь

- **API** — набор функций, которыми одна программа пользуется у другой.
- **APK** — файл-установщик Android-приложения.
- **Build / сборка** — превращение исходников в файлы, которые понимает браузер.
- **CI/CD** — автоматические проверки и публикация при каждом изменении (у нас GitHub Actions).
- **Commit / push** — сохранить снимок изменений / отправить коммиты на GitHub.
- **Dependency (зависимость)** — чужая библиотека из npm, список — в `package.json`,
  точные версии — в `package-lock.json`, сами файлы — в `node_modules/` (не коммитится).
- **Foreground service** — Android-служба с постоянным уведомлением, которую система не усыпляет.
- **Hook (хук)** — функция React с именем `use…`, дающая компоненту состояние или эффекты.
- **HTTPS / защищённый контекст** — шифрованное соединение; без него браузер прячет GPS и др.
- **IndexedDB** — база данных внутри браузера.
- **JSX** — HTML-подобная запись внутри JavaScript: `<Button>Старт</Button>`.
- **Lint** — автоматический поиск подозрительного кода.
- **Migration (миграция)** — обновление схемы базы без потери старых данных.
- **npm** — менеджер пакетов JavaScript и запуск команд (`npm run …`).
- **PWA** — сайт, который ставится на экран и работает без интернета.
- **Repository (репозиторий)** — 1) папка проекта с историей Git; 2) в коде — объект
  доступа к таблице базы (`runsRepo`).
- **Service worker** — фоновый скрипт сайта, кэширует файлы для работы офлайн.
- **Soft delete (мягкое удаление)** — запись помечается удалённой, но остаётся в базе.
- **UUID** — случайный уникальный идентификатор вида `3f2a…`.
- **WebView** — встроенный браузер внутри Android-приложения.

## 16. Что изучать и в каком порядке

1. **JavaScript** — переменные, функции, массивы (`map`, `filter`, `reduce`), объекты,
   `async/await` и `Promise`. Без этого остальное не пойдёт.
   Ресурс: [learn.javascript.ru](https://learn.javascript.ru) — лучший учебник на русском.
2. **TypeScript** — типы, `interface`, `type`, объединения (`'run' | 'walk'`).
   Практика: открой `src/domain/run.ts` и `src/domain/types.ts`, прочитай типы.
   Ресурс: официальный Handbook на typescriptlang.org.
3. **React** — компоненты, props, `useState`, `useEffect`.
   Ресурс: [react.dev/learn](https://react.dev/learn) (есть русский перевод — ru.react.dev).
   Практика: `src/components/Stepper.tsx` — маленький компонент целиком.
4. **CSS** — flex, grid, переменные. Практика: `src/app/theme.css`, любой `.module.css`.
5. **Git** — `status`, `diff`, `add`, `commit`, `log`, `push`. Ресурс: книга Pro Git
   (git-scm.com/book/ru).
6. **Тесты** — открой `tests/oneRM.test.tsx`, поменяй ожидаемое число, запусти — увидишь,
   как выглядит падение.
7. **IndexedDB и Dexie** — dexie.org, раздел Tutorial. Практика: `src/data/db.ts` и
   `src/data/repositories/notes.ts` (самый простой репозиторий).
8. **Android и Kotlin** — когда захочется своих нативных функций: kotlinlang.org, затем
   документация Capacitor «Creating plugins». Практика: `ShareImagePlugin.kt` — самый
   короткий плагин.

**Как учиться на этом проекте.** Возьми маленькую функцию из `src/domain/` (например,
`plates.ts` — раскладка блинов на гриф), прочитай её и тест к ней
(`tests/plates.test.ts`), потом попробуй что-то поменять и запусти тесты. Затем найди, на
каком экране она используется (поиск по имени функции в редакторе), и посмотри, как экран
её вызывает. Так по одной ниточке разбирается весь проект.

В браузере на компьютере: `npm run dev` → открыть сайт → F12 → вкладка **Application →
IndexedDB → fitnes** — там видно все таблицы и записи вживую.
