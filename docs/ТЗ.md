# ТЗ: Личное фитнес-приложение

24 сентября 2026

## 1. Цель и контекст

Нужно мобильное веб-приложение для одного человека: составлять программы тренировок, вести тренировку в зале и видеть прогресс по весам. Без регистрации, рекламы и соцфункций.

- **Пользователь:** один, владелец приложения.
- **Устройство:** смартфон (iOS/Android), в браузере или установленное на главный экран (PWA).
- **Главный сценарий:** открыть в зале → выбрать день программы → отмечать подходы одной рукой за 2–3 касания.
- **Порядок работ:** сначала утверждаем ТЗ и архитектуру, затем разработка по этапам из раздела 6.

## 2. Функциональные требования

Приложение состоит из пяти блоков: справочник упражнений, программы, тренировка, история, прогресс.

### 2.1 Справочник упражнений

1. Стартовый набор из ~100 упражнений: штанга, гантели, тренажёры, блоки, свой вес, пресс, кардио. Когда набор пополняется, недостающие упражнения добавляются у всех при следующем запуске.
2. Добавление, редактирование, удаление своих упражнений.
3. Поля: название, группа мышц (грудь, спина, ноги, плечи, руки, пресс, кардио), тип (вес × повторения / собственный вес / время), заметка.
4. Поиск по названию и фильтр по группе мышц.

### 2.2 Программы (планы тренировок)

1. Программа = название + список дней (напр. «День A — грудь/трицепс»).
2. В дне — упражнения в заданном порядке; для каждого: количество подходов, повторения (число или диапазон 8–12), целевой вес, отдых между подходами (сек).
3. Перестановка упражнений вверх/вниз, копирование дня и программы.
4. Одна программа отмечается активной; приложение предлагает следующий день по кругу.

### 2.3 Тренировка (режим «в зале»)

1. Старт из дня программы или пустой тренировки.
2. Поля подхода заполняются из прошлой тренировки (вес и повторения); прошлый результат показан рядом.
3. Кнопки ±2,5 кг и ±1 повторение; отметка «выполнено» одним касанием.
4. После отметки подхода запускается таймер отдыха с вибрацией/звуком.
5. Добавить/удалить подход или упражнение на ходу; заметка к тренировке.
6. Таймер общей длительности; незавершённая тренировка не теряется при закрытии вкладки.
7. «Завершить» → сводка: время, тоннаж, новые рекорды.

### 2.4 История

1. Список тренировок (новые сверху): дата, название, длительность, тоннаж.
2. Просмотр, редактирование и удаление прошедшей тренировки.

### 2.5 Прогресс

1. По каждому упражнению: график лучшего веса и расчётного 1ПМ по датам.
2. Личные рекорды: макс. вес, макс. 1ПМ, макс. объём за подход.
3. Общая статистика: тренировок за неделю/месяц, тоннаж по неделям.
4. Вес тела (v2): ручной ввод и график.

1ПМ считается по формуле Эпли: **1ПМ = вес × (1 + повторения / 30)**.

## 3. Модель данных

Шесть сущностей; фактические подходы хранятся отдельно от плана, чтобы правка программы не меняла историю.

| Сущность | Поля |
| --- | --- |
| Exercise | id, name, muscle, type (weight/bodyweight/time), note |
| Program | id, name, isActive, days[] |
| ProgramDay | id, name, items[] — { exerciseId, sets, repsMin, repsMax, weightKg, restSec } |
| Workout | id, date, programId?, dayId?, startedAt, finishedAt, note, entries[] |
| WorkoutEntry | exerciseId, sets[] |
| Set | weightKg, reps, done, timeSec? |

Тоннаж тренировки = Σ (weightKg × reps) по выполненным подходам. Единицы — килограммы.

## 4. Экраны и сценарии

Нижняя панель из четырёх вкладок; активная тренировка открывается поверх всего.

| Экран | Что на нём |
| --- | --- |
| Сегодня | следующий день активной программы, кнопка «Начать», статистика недели, последняя тренировка |
| Программы | список программ → дни → упражнения с подходами/повторами/весом |
| Тренировка | карточки упражнений, строки подходов, таймер отдыха внизу |
| История | список прошедших тренировок и детали |
| Прогресс | выбор упражнения → график и рекорды |
| Упражнения | справочник (из вкладки «Программы») |

Основной цикл в зале:

1. Сегодня → «Начать день».
2. Отметить подход.
3. Таймер отдыха → следующий подход (шаги 2–3 повторяются).
4. «Завершить» → сводка и рекорды.

## 5. Нефункциональные требования

- **Мобильный UI:** ширина от 360 px, кнопки не меньше 44×44 px, основные действия в нижней трети экрана.
- **Темы:** светлая и тёмная по настройке системы.
- **Скорость:** открытие < 1 с, отклик на касание < 100 мс.
- **Хранение:** данные сохраняются автоматически после каждого изменения; сервер не обязателен.
- **Офлайн:** тренировка работает без интернета (в зале часто нет сети).
- **Резервная копия:** экспорт и импорт всех данных в JSON-файл.
- **Язык:** русский; единицы — кг, шаг веса 2,5 кг (настраиваемый).
- **Экран не гаснет** во время активной тренировки (Wake Lock API, где доступно).

## 6. Технологии и этапы

Рекомендация: PWA на чистом HTML/JS (или React + Vite), данные в IndexedDB, без сервера. Это бесплатно, ставится на главный экран и не требует публикации в App Store / Google Play.

| Этап | Состав |
| --- | --- |
| MVP | справочник упражнений, программы, режим тренировки с таймером, история, график по упражнению, экспорт/импорт JSON |
| v2 | офлайн-установка (service worker), вес тела, подсказка прогрессии (+2,5 кг при выполнении всех повторений), суперсеты |
| v3 | синхронизация между устройствами (напр. Supabase), календарь тренировок |

Ориентир по срокам MVP: 2–3 недели вечерней работы одного разработчика.

## 7. Архитектура

Клиентское приложение без сервера (local-first): вся логика и данные на телефоне, синхронизация — отдельный адаптер, который добавляется в v3 без переделки остального кода.

### 7.1 Стек

| Слой | Выбор | Почему |
| --- | --- | --- |
| Язык | TypeScript | типы для модели данных и миграций |
| UI | React + Vite | быстрая сборка, много готовых решений |
| Навигация | React Router | 4 вкладки + вложенные экраны |
| Состояние | Zustand | простой глобальный стор для активной тренировки |
| Хранилище | IndexedDB через Dexie.js | объём без лимита localStorage, индексы, миграции схемы, `useLiveQuery` |
| Графики | свои SVG-компоненты | нужны всего два вида графиков; без библиотеки сборка меньше, а цвета и подсказки по касанию под полным контролем |
| Офлайн | vite-plugin-pwa (Workbox) | кэш файлов, установка на главный экран |
| Стили | CSS-модули + CSS-переменные | светлая/тёмная тема через токены |
| Тесты | Vitest + fake-indexeddb | расчёты 1ПМ, тоннажа, рекордов, импорт/экспорт |
| Хостинг | GitHub Pages / Netlify / Vercel | бесплатно, HTTPS обязателен для PWA |
| Синхронизация (v3) | Supabase (Postgres + Auth) | бесплатный тариф, один пользователь |

### 7.2 Слои приложения

| Слой | Отвечает за | Обращается к |
| --- | --- | --- |
| Экраны и компоненты | отображение, ввод | стор, домен, репозитории |
| Стор (Zustand) | активная тренировка, таймер отдыха | репозитории |
| Домен | расчёты 1ПМ, тоннажа, рекордов, прогрессии | — (чистые функции) |
| Репозитории | чтение/запись сущностей | IndexedDB, адаптер синхронизации (v3) |
| IndexedDB / Dexie | хранение на устройстве | — |
| Адаптер синхронизации (v3) | обмен изменениями с Supabase | Supabase |
| Service worker | кэш файлов приложения для офлайна | — |

Экраны не обращаются к базе напрямую — только через репозитории; доменные функции чистые и покрыты тестами.

### 7.3 Хранение (IndexedDB)

| Таблица | Ключ и индексы | Содержимое |
| --- | --- | --- |
| exercises | id, muscle, name | справочник, стартовый набор сидится при первом запуске |
| programs | id | программа с вложенными днями и планом |
| workouts | id, date, status, *exerciseIds | тренировка с вложенными упражнениями и подходами |
| meta | key | версия схемы, шаг веса, активная программа, указатель «следующий день» |

Мульти-индекс `*exerciseIds` даёт быстрый запрос «все тренировки с этим упражнением» для графика и подстановки прошлых весов. Активная тренировка — обычная запись в workouts со `status = 'active'`. Поле `status` нужно потому, что IndexedDB не индексирует `null` и булевы значения; по той же причине активная программа хранится в meta, а не флагом в programs.

### 7.5 Ключевые решения

1. **План отделён от факта.** При старте тренировки день программы копируется в Workout; правка программы не меняет историю.
2. **Сохранение на каждое действие.** Активная тренировка пишется в IndexedDB после каждой отметки (ввод с задержкой ~500 мс) — закрытие вкладки ничего не теряет.
3. **Метрики вычисляются, а не хранятся.** Тоннаж, 1ПМ и рекорды считаются из подходов, поэтому правка старой тренировки сразу меняет статистику.
4. **Таймер по метке времени.** Хранится `restEndsAt`, а не остаток секунд — таймер верен после сворачивания и блокировки экрана.
5. **Готовность к синхронизации.** UUID вместо счётчиков, поля `updatedAt` и `deletedAt` (мягкое удаление) во всех сущностях с первой версии.
6. **Версионирование схемы.** Миграции Dexie (`db.version(n).upgrade`) и поле `version` в файле экспорта.
7. **Ограничения iOS.** Вибрация в Safari недоступна — конец отдыха сигналит звуком и цветом; Safari может очистить данные неустановленного сайта, поэтому приложение ставится на главный экран и запрашивает `navigator.storage.persist()`, а раз в неделю напоминает про экспорт.

## 8. Критерии приёмки

- [ ] Программа из 3 дней по 5 упражнений создаётся меньше чем за 5 минут.
- [ ] Подход отмечается одним касанием, если вес и повторения совпали с планом.
- [ ] После отметки подхода запускается таймер отдыха с сигналом в конце.
- [ ] Перезагрузка страницы посреди тренировки не теряет введённые подходы.
- [ ] Следующая тренировка того же дня подставляет веса и повторения из прошлой.
- [ ] График прогресса показывает лучший вес и 1ПМ по датам.
- [ ] Экспорт → очистка → импорт восстанавливает все данные без потерь.
- [ ] На экране 360 px нет горизонтальной прокрутки.

## 9. Доработки версии 1.1

Шесть изменений по отзыву после первых тренировок. Цель — сделать интерфейс компактнее, вынести вес тела в отдельный раздел и дать вносить тренировки вручную.

### 9.1 Компактный интерфейс

1. Сократить длинные описания: подсказки в пустых разделах, пояснения в настройках, подписи под кнопками. Оставить одну короткую фразу или убрать совсем, если и так понятно.
2. Уменьшить поля ввода подходов в тренировке (вес, повторы, кнопки ±). Строка подхода должна быть заметно ниже нынешних 48 px, а касание — по-прежнему удобным (кнопки ± не меньше 36 px).
3. Там же подровнять отступы карточек упражнений, чтобы на экране помещалось больше подходов.

### 9.2 Раздел «Вес»

1. Отдельный раздел «Вес» — пятая вкладка нижней панели — вместо блока «Вес тела» на экране «Прогресс». На экране «Прогресс» остаётся только график веса (п. 9.6).
2. Ввод веса и выбор времени взвешивания:
    - **Утром** — записывается введённый вес как есть.
    - **Днём / вечером / после тренировки** — из введённого веса вычитается 1,5 кг, и записывается итоговый вес. Поправка всегда 1,5 кг, в настройках не меняется.
3. В записи хранятся введённый вес, время взвешивания и итоговый вес. В истории видны оба значения, например «вечер: 82,0 → 80,5 кг».
4. История записей с удалением и график итогового веса.
5. Одна запись на день, как сейчас: новая запись за тот же день заменяет прежнюю.

### 9.3 Добавить тренировку вручную в «Истории»

1. Кнопка «Добавить тренировку» на вкладке «История».
2. Дата: сегодня, любой прошедший или будущий день.
3. Заполнение: название, упражнения из справочника, подходы с весом и повторами, заметка. Можно начать с дня программы или с пустой тренировки.
4. Тренировка за сегодня или прошедший день сразу считается завершённой и попадает в историю, рекорды и прогресс.
5. Тренировка на будущую дату — это **запланированная** тренировка. В тот день она появляется на экране «Сегодня» с кнопкой «Начать» вместо следующего дня программы. До выполнения в статистике не учитывается; в «Истории» видна в отдельном блоке «Запланировано» с возможностью изменить или удалить.

### 9.4 Экран «Сегодня» удобнее и красивее

1. Главное наверху: крупная карточка следующей тренировки с кнопкой «Начать» в зоне большого пальца.
2. Короче и нагляднее: план дня — компактным списком, статистика недели — одной строкой или мини-графиком.
3. Быстрые действия: записать вес, свободная тренировка, повторить прошлую.
4. Конкретный вид согласовать отдельно: сделать 2 варианта на выбор, как с оформлением на этапе 2.

### 9.5 Бокс

1. Новая группа упражнений «Бокс» в справочнике:
    - бой с тенью (время);
    - бой с тенью с гантелями (время);
    - прямые удары с гантелями (джеб/кросс, повторы);
    - боковые удары с гантелями (хук, повторы);
    - апперкоты с гантелями (повторы);
    - работа на мешке (раунды, время);
    - работа на лапах (раунды, время);
    - уклоны и нырки (время).
2. Готовая программа «Бокс» среди типов программ (п. 2.2): 2–3 дня, например «Техника и удары», «Выносливость», «Сила для бокса». Работа раундами по времени с отдыхом между раундами.

### 9.6 Экран «Прогресс»

1. Убрать график «Тоннаж по неделям».
2. Вместо него — графики, которые переключаются кнопками-переключателями над графиком:
    - **Вес тела** — итоговый вес по датам (данные из раздела «Вес»);
    - **Рабочий вес** — рабочий вес в выбранном упражнении по тренировкам. Рабочий вес тренировки — вес, с которым сделано больше всего подходов; при равенстве — больший из них;
    - **Подходы** — успехи по подходам: сколько повторов и подходов сделано в упражнении по тренировкам.
3. Рекорды по упражнению и таблица последних тренировок остаются.

### 9.7 Решения

Ответы от 25 сентября 2026 на вопросы к доработкам:

1. **Раздел «Вес»** — пятая вкладка внизу (пока; можно пересмотреть после использования).
2. **Поправка за взвешивание не утром** — всегда 1,5 кг, без настройки.
3. **Тренировка на будущую дату** — план: появляется на экране «Сегодня» в свой день (пока так; пересмотреть после использования).
4. **Рабочий вес** — вес, с которым сделано больше всего подходов; если таких весов несколько — больший.
5. **Экран «Сегодня»** — вариант «Список»: неделя кружками сверху, план дня списком, быстрые действия строкой, кнопка «Начать» закреплена внизу. На «Сегодня» же — запись сегодняшнего веса.
6. **Раздел «Вес»** — список по дням с отдельной колонкой разницы с прошлой записью (минус — похудел, плюс — набрал), сверху итоги: сейчас, за 30 дней, с первой записи.
